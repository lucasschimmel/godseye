## Confirmed defects

### R1 — P1: changing a definition retries an old protected unknown effect

Evidence: `packages/core/src/jobs-definitions.ts:62` updates handler/policy/limits in place. `packages/core/src/jobs-sync.ts:79` reads that current definition; retry decisions at lines 20–22 and 54–58 can then requeue an older run.

An independent in-memory fixture executed a protected job returning `unknown`, re-registered the same definition as `idempotent`, then ticked the engine. The old run changed from `{state:"unknown",attempt:1}` to `{state:"queued",attempt:2}` without reconciliation. This violates F21/T18 and ADR-011 decision 5.

Counterargument: the owner authorized the new definition. This does not establish absence of the old external effect or resolve that run. Freeze the definition and effect policy per run, or prevent redefinition from relaxing existing uncertain effects.

### R2 — P2: a hanging outbox sender stalls the global scheduler

Evidence: `packages/core/src/jobs-outbox.ts:224` awaits `sender.send()` without a bound; line 276 awaits each send sequentially. Unknown-effect probes at line 162 are also unbounded. `packages/core/src/jobs-scheduler.ts:160` and `packages/core/src/jobs.ts:177` wait for completion before the next tick. The configured dispatch timeout at `jobs-outbox.ts:129` only detects stale claims on a later tick.

A controlled sender promise kept `jobs.tick()` pending until explicitly released; a 200 ms race observed `blocked`. This demonstrates absence of a central deadline, not a production latency benchmark. A sender-specific timeout would help, but the interface does not require it and central liveness currently depends on it. Bound sends/probes, preserve uncertainty on expiry and allow shutdown without claiming a stopped external effect.

### R3 — P2: approval renewal bypasses the heavy queue bound

Evidence: `packages/core/src/infra-heavy.ts:54` excludes `awaiting_approval`; `packages/core/src/foundation-plans.ts:255` requeues an approved waiting run without capacity admission.

A disposable PGlite probe queued a heavy DB backup, expired its approval, claimed it into `awaiting_approval`, filled the available five admitted slots, then reapproved the old run. Counts became `{running:0,queued:6}` under `{maxConcurrent:1,maxQueued:4}`. The concurrent execution cap still works; the finite queue bound does not. Reserve waiting capacity or atomically admit requeued work.

### R4 — P2: Jenkins discards browser failure traces

Evidence: `playwright.config.ts:85` writes `artifacts/playwright-results`; lines 90–91 retain traces/screenshots. `Jenkinsfile:99` archives `artifacts/playwright/**,artifacts/ci/**`, then line 100 deletes the workspace. `scripts/ci-report.mjs` records metadata, not copies of these files. JUnit retains statuses, not the missing diagnostic artifacts. Archive the actual output path before cleanup.

- **R1:** changed definitions return `JOB_DEFINITION_BUSY` (409) while any run is outside
  `succeeded|failed|cancelled`. Identical content remains allowed; only terminal resolution
  permits changing the old definition. Rejection preserves revision and mutation receipt.
- **R2:** central `dispatchTimeoutMs` deadlines bound sends and read-only probes; the pump
  propagates abort. Send timeout preserves `unknown`, inconclusive probe becomes
  `reconciling`, and late results are ignored. One active-call slot per environment/destination
  remains until actual promise settlement, with 50 slots per engine; busy scopes are excluded
  before the pending-row limit. Optional provider signals support cooperative cancellation,
  without claiming physical effects stopped. The timeout is validated as a positive safe
  integer up to the Node timer maximum, 2,147,483,647 ms (default 60,000 ms).
- **R3:** the trusted infrastructure `requeueAdmission` hook checks heavy capacity under the
  existing approval transaction for nonterminal `awaiting_approval` runs only. Full capacity
  returns 429 and rolls back approval/receipt/audit/run changes. It does not repeat physical
  reservation or requeue queued/running/terminal work.
- **R4:** Jenkins retains actual `artifacts/playwright-results/**` diagnostics before deleting
  its workspace, preserving the existing archive patterns too.
