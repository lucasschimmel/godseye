# Database acceptance test strategy

Generated by GAUNTLET, run godseye-local-database, 2026-11-11. Production criticity; TypeScript strict, Vitest 5.1.0 / Playwright 1.65.0. Spec-first cases drafted before database implementation inspection. Existing baseline: 325 unit/integration and 18 browser tests; no baseline replacement.

## Criteria and fault matrix

| Criterion | Behavior oracle | Layer and faults |
| --- | --- | --- |
| AC-27 | Project/environment mutations replay exactly once, reject key reuse/stale revisions and foreign ancestry; previews have finite expiry; metadata never proves physical suspension | Core and HTTP: rename, conflicting concurrent edits, preview expiry/name/limit boundaries, production/development preservation |
| AC-28 | Profile is strict, bounded and immutable; independent cell mappings and roles originate on server | Unit/property: unknown fields, SQL/path/endpoint/provider injection, engine/version mismatch, nonfinite/oversized connection/storage/WAL/temp budgets, deterministic hashes and scope separation |
| AC-29 | Only exact fresh owner authority admits database effects through the shared Foundation queue; one cell/capacity reservation wins | Core integration: stale owner, foreign project/environment, changed profile/hash/revision, unsupported intents, generic Foundation enqueue bypass, concurrent double admission, no qualified provider |
| AC-30 | Compiled bootstrap/HBA/settings implement scoped service permissions and finite limits; live effective settings are independently inspected | Unit compiler assertions plus separately owned native PostgreSQL lab: runtime DML vs migration DDL, auth/workflow separation, analysis sanitized reads, PUBLIC/default privileges, privileged role flags |
| AC-31 | Owner-visible contracts contain references only; private material and transport policy cannot be caller-supplied | Core/HTTP negative schema and exception redaction; private driver material fault; native lab wrong/no TLS, cross-cell credentials, SCRAM, restrictive IPv4/IPv6 HBA |
| AC-32 | Persist before effects; restarts reconcile exact identity, preserve uncertainty/reservations; never adopt foreign clusters or erase data | Qualified provider fixture: lost acknowledgment after side effect, before-effect failure, partial provision, restart, cancellation/fencing during await, changed generation, wrong cell/allocation/profile identity, replay and concurrent tick |
| AC-33 | Authenticated owner HTTP/client routes are strict and accurate; unavailable state never appears provisioned | HTTP/client: no session/service proof, stale session, missing idempotency key, malformed profile, replay, response DTO redaction, real OpenAPI paths, unsupported SQL/delete/export/restore routes |
| AC-34 | Separate real PG18 instances execute production bootstrap/inspection and negative isolation/transport cases | Independently owned `pg-lab*`; fixture tests expressly do not qualify native/VM/container containment |

## Contract critique before implementation

1. The prepare contract must bind both project and environment revisions in the immutable hash; replay of an old preparation cannot authorize a metadata-edited scope.
2. `intent: suspend/resume` must require an existing verified exact cell and fresh owner authority, preserve reservations where effects remain unknown, and avoid changing actual state from a metadata request.
3. A provider boolean or desired inventory cannot qualify execution. Admission needs independently observed provider/target/generation evidence and runtime rechecks after awaits.
4. Compiler output must be generated solely from validated bounded profile and server IDs; bootstrap admin and per-role material stay private. Returned bootstrap strings must not accidentally become owner-visible material.
5. The generic Foundation plan/enqueue path is an alternate authority boundary, so every database capability needs matching hooks even if normal HTTP only exposes preparation/admission.
6. A provider acknowledgment alone cannot prove correct roles, TLS, limits, PGDATA/WAL independence or cell ownership. Independent exact inspection must settle success; failures after dispatch remain unknown until reconciliation.
7. Replay behavior, lease loss, restart and late effects require durable cell/allocation identity rather than name matching. Never repair an identity mismatch by adopting or deleting the foreign instance.

## Execution order and limits

Implement compiler/schema cases first (small), then revision/lifecycle and shared-queue authority (medium), provider failure/recovery/concurrency (large), HTTP/client boundaries (medium). Browser journey and actual PostgreSQL lab have separate owners. Run targeted files only while the production worker is active; full suite and curated mutations follow contract freeze under root coordination. Selected mutants must remove an actual authority/identity/uncertainty guard and be killed by observable assertions. Coverage/mutation results are reported as measured or unmeasured, never inferred from test count. No external production APIs, server access, system changes, or global installs.
